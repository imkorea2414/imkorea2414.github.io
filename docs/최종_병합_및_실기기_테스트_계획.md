## 2. 최종 병합 순서 (사용자 승인 후)

1. **원전 확인 대기 항목**(CLAUDE.md 7장)을 이번 출시에서 어떻게 할지 결정한다. 원전 확인 없이 바꾸지 않는다.
2. `claude/release-prep`에서 전체 회귀 테스트 한 번
   - 로컬 Chromium: `python3 -m http.server 8765` 를 켠 상태에서 `python3 tests/run_all.py` (16개)
   - GitHub: push 때 App tests (Chromium·WebKit) 확인
   - WebKit에서 실행되지 않는 단계(오프라인)는 통과로 적지 않는다
3. main을 `claude/release-prep`으로 옮긴다 (main이 그사이 바뀌지 않았으면 빨리 감기, 아니면 병합 커밋).
4. Pages 배포 확인
   - main push로 Deploy Pages가 자동 실행된다 → `verify-live` 작업 통과 확인 (서비스 파일, assetlinks 일치, 개인정보처리방침을 연 뒤 오프라인 앱, 오프라인 개인정보처리방침, 개발 문서·원전 이미지 404)
   - 지금 공개 사이트는 옛 서비스 워커(sr-v1)라 '개인정보처리방침을 연 뒤 오프라인 앱'이 알려진 문제로 표시된다(11/19 실제 사이트에서 재현 확인). 병합 뒤 sr-v2가 배포되면 엄격하게 검사된다
   - 배포된 서비스 워커가 `sr-v2`면 오프라인 개인정보처리방침도 엄격하게 검사된다
5. 문의 이메일을 받으면 `privacy.html` 두 곳에 넣고 다시 배포한다.
6. Play 앱 서명 키 지문을 받으면 `.well-known/assetlinks.json`에 추가하고 다시 배포한다 (업로드 키 지문은 지우지 않는다).
7. APK·AAB 다시 만들기는 **별도 승인 후**. 웹 수정만으로는 다시 만들 필요가 없다 (TWA는 웹을 연다). 다시 만들 때는 `android/**` 변경이 없으므로 Actions → Android app bundle → Run workflow로 수동 실행한다.

## 3. 실기기 테스트 계획

확인 항목 (기기마다 `docs/실기기_테스트_체크리스트.md`, `docs/기기별_테스트_가이드.md`와 함께)

| # | 항목 | 방법 | 기대 결과 |

| 1 | 앱 실행·주소창 | APK 실행 | 주소창 없이 열림 (Play 설치판은 앱 서명 키 지문 추가 뒤 확인) |

| 3 | 개인정보처리방침 뒤 오프라인 | 온라인에서 privacy.html 열기 → 비행기 모드 → 앱 실행 | 앱이 열림 (예전 오류: 개인정보처리방침이 열림) |
| 4 | 업데이트 뒤 기록 유지 | 기존에 쓰던 기기에서 온라인으로 한 번 연 뒤 오프라인 실행 | Day 진행·기록 그대로 |

## 4. Git 기록에 남은 원전 자료 제거 계획 (미승인, 실행하지 않음)

남아 있는 것: 2026-11-19 이전 커밋의 `docs/훈련투입방법_원본표.png`, `tools/count_check.py`의 원전 본문 5줄.

권장 시점: **최종 병합 직후** (브랜치가 main 하나로 줄었을 때). 그때까지 옛 커밋 주소로는 볼 수 있다.

순서

1. 개발 브랜치를 모두 main에 합치고 정리한다 (강제 push 대상 최소화).
2. 전체 기록 복제와 되돌리기용 백업 (비공개 보관)
   ```bash
   git clone --mirror https://github.com/imkorea2414/imkorea2414.github.io.git repo-mirror.git
   ```
   ```bash
   git -C repo-mirror.git bundle create ../before-rewrite.bundle --all
   ```
3. `git filter-repo`로 이미지 경로 제거 + 원전 문장 치환
   - 치환 규칙 파일(원전 문장 → 대체 문구)은 **비공개로 만들고 저장소에 넣지 않는다.** 원전 문장은 옛 커밋의 `tools/count_check.py` 3~6줄에 있다.
   ```bash
   git -C repo-mirror.git filter-repo --invert-paths --path 'docs/훈련투입방법_원본표.png' --replace-text ../replacements.txt
   ```
4. 확인: 기록 전체에서 이미지 경로·원전 문장 검색 0건, 최신 커밋의 파일 내용이 재작성 전과 같음(특히 `index.html`, `sw.js`, `.well-known/assetlinks.json`, `android/`).
5. 원격 주소를 다시 넣고 강제 push (filter-repo는 원격 설정을 지운다)
   - 이 작업 환경은 브랜치 삭제가 막혀 있어 강제 push도 막힐 가능성이 크다. 그러면 사용자 컴퓨터에서 실행한다.
6. GitHub 고객지원에 옛 커밋 캐시 삭제를 요청하고, 처리 뒤 옛 커밋 주소가 404인지 확인한다 (현재 절차는 직접 확인하지 못함).
7. 모든 옛 복제본(사용자 컴퓨터, 다른 세션)은 버리고 새로 받는다. 옛 복제본에서 push하면 이미지가 다시 올라온다.

영향: Pages·TWA·서명 키·assetlinks·기존 APK/AAB는 영향 없음 (주소·파일 내용 그대로). 앞쪽 4개를 뺀 모든 커밋 번호가 바뀌고, Actions 옛 실행 기록의 커밋 링크가 깨질 수 있다.
