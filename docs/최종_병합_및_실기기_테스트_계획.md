### 4-1. 준비 (사용자 컴퓨터 권장)

이 작업 환경은 원격 브랜치 삭제가 막혀 있어 강제 push도 막힐 가능성이 크다. 아래 명령은 사용자 컴퓨터(Git 2.36 이상, Python 3)에서 실행하는 것을 기준으로 한다.

```bash
pip install git-filter-repo
```

### 4-2. 백업 (되돌리기용, 비공개 보관 — 원전 자료가 들어 있으므로 어디에도 올리지 않는다)

```bash
git clone --mirror https://github.com/imkorea2414/imkorea2414.github.io.git repo-mirror.git
```
```bash
git -C repo-mirror.git bundle create ../before-rewrite.bundle --all
```
```bash
git -C repo-mirror.git bundle verify ../before-rewrite.bundle
```

### 4-3. 치환 규칙 파일 만들기 (원전 문장을 문서에 적지 않고, 옛 커밋에서 자동으로 꺼낸다)

```bash
git -C repo-mirror.git show 10c42bb:tools/count_check.py | python3 -c "import sys,re; [print(m+'==>(\"[원전 문장 삭제]\",0)') for m in re.findall(r'\\(\"[^\"]+\",\\d+\\)', sys.stdin.read())]" > replacements.txt
```

`replacements.txt`에 5줄이 생겼는지 확인한다 (이 파일도 비공개, 작업 후 삭제). 규칙은 반드시 `("문장",숫자)` 묶음 전체를 대상으로 한다: 원전 줄 가운데 아주 짧은 줄이 있어, 문장만 대상으로 하면 앱 본문 등 다른 파일의 같은 글자까지 바뀐다 (2026-11-19 시험에서 확인).

### 4-4. 기록 다시 쓰기

```bash
git -C repo-mirror.git filter-repo --invert-paths --path 'docs/훈련투입방법_원본표.png' --replace-text ../replacements.txt
```

### 4-5. 확인 (모두 통과해야 push)

```bash
git -C repo-mirror.git log --all --oneline -- 'docs/훈련투입방법_원본표.png'
```
→ 아무것도 나오지 않아야 한다.
```bash
git -C repo-mirror.git grep -c -F -f <(sed 's/==>.*//' replacements.txt) $(git -C repo-mirror.git rev-list --all) | head
```
→ 아무것도 나오지 않아야 한다.
재작성 **전에** 4-4 앞에서 `git -C repo-mirror.git ls-tree -r main > before_tree.txt` 를 저장해 두고, 재작성 뒤 비교한다.
```bash
diff <(awk '{print $3, $4}' before_tree.txt) <(git -C repo-mirror.git ls-tree -r main | awk '{print $3, $4}')
```
→ 아무것도 나오지 않아야 한다 (최신 main의 모든 파일 내용이 그대로). 첫 커밋의 파일 내용(트리)도 그대로인지 본다 (`5e91f45df7…`로 시작해야 한다):
```bash
git -C repo-mirror.git rev-parse $(git -C repo-mirror.git rev-list --max-parents=0 main)^{tree}
```

### 4-6. 올리기

```bash
git -C repo-mirror.git remote add origin https://github.com/imkorea2414/imkorea2414.github.io.git
```
```bash
git -C repo-mirror.git push --force --mirror origin
```

`--mirror`는 원격 브랜치를 로컬과 똑같이 맞춘다 (로컬에 없는 원격 브랜치는 지워진다). 브랜치를 main 하나로 줄인 뒤에 실행한다.

### 4-7. 뒷정리

1. GitHub 고객지원에 옛 커밋 캐시 삭제를 요청하고, 처리 뒤 옛 커밋 주소(예: `.../blob/10c42bb/...`)가 404인지 확인한다 (현재 절차는 직접 확인하지 못함).
2. 다른 모든 복제본(사용자 컴퓨터, 다른 Claude 세션)은 지우고 새로 받는다. 옛 복제본에서 push하면 이미지가 다시 올라온다.
3. main push로 Pages가 다시 배포되고 `verify-live`가 돈다. 통과를 확인한다.
4. 문서·대화에 적힌 옛 커밋 번호는 더 이상 쓸 수 없다.

### 4-8. 문제가 생기면 되돌리기

```bash
git clone --mirror before-rewrite.bundle restore.git
```
```bash
git -C restore.git push --force --mirror https://github.com/imkorea2414/imkorea2414.github.io.git
```

되돌리면 원전 자료도 다시 공개 기록에 올라가므로, 원인을 고쳐 4-3부터 다시 하는 것이 우선이다.

### 4-9. 영향

| 대상 | 영향 |
|---|---|
| GitHub Pages | 주소·배포 파일 그대로. push 때 다시 배포 |
| Android TWA, assetlinks.json, 서명 키 | 영향 없음 (도메인·파일 내용 그대로, 키는 저장소에 없음) |
| 기존 APK·AAB | 그대로 사용 가능. 다음 빌드 번호는 실행 번호라 계속 커짐 |
| GitHub Actions | 비밀값 그대로. 옛 실행 기록의 커밋 링크는 깨질 수 있음 |
| 브랜치·커밋 | **모든 커밋 번호가 바뀜.** 파일 내용은 그대로지만 `filter-repo`가 커밋의 전자 서명을 지우기 때문에 첫 커밋부터 번호가 달라지고, GitHub의 "Verified" 표시도 사라진다 (2026-11-19 시험에서 확인, 11/20 다시 확인: 서명 45/45 → 0) |
| 기존 PR·태그·포크 | 11/20 확인: PR 0개(열린 것·닫힌 것 모두), 태그 0개, 포크 0개 → 영향받는 것 없음 |
| 브랜치 보호 | 11/20 확인: 5개 브랜치 모두 보호 없음, main 규칙(ruleset) 없음 → 강제 push를 막는 설정 없음. (보호 설정 상세 API는 이 작업 환경에서 열람 불가 → 강제 push 전에 Settings → Branches에서 한 번 더 확인) |
| GitHub Actions 실행 | main 강제 push → `pages.yml`(경로 조건 없음)이 돌아 **같은 내용으로 다시 배포**된다. `tests.yml`·`android.yml`은 경로 조건이 있어, 파일 내용이 같으면 돌지 않을 것으로 보인다 (추론, 확인 못 함). 혹시 Android 빌드가 돌면 안 되므로 강제 push 전에 "Android app bundle"을 Disable해 두는 것을 권한다 |
| Pages 환경 | `github-pages` 배포 환경의 브랜치 조건(main)은 브랜치 이름이 같아 그대로 (이 작업 환경에서는 환경 설정 API 열람 불가) |
| 다른 작업 환경 | 이 Claude 세션의 복제본, 사용자 컴퓨터의 복제본, 다른 Claude 세션은 **모두 지우고 새로 받는다.** 옛 복제본에서 push하면 옛 기록(원전 그림 포함)이 다시 올라간다. claude.ai 프로토타입 아티팩트는 저장소와 무관 |
| 문서 속 커밋 번호 | 이 문서의 `10c42bb`(4-3 규칙 추출에 사용 — 재작성 전에만 유효), `docs/실기기_최종_테스트.md`의 `06a84fa`. 재작성 뒤 새 번호로 고친다 |
| 이 작업 환경에서의 실행 | 이 환경은 원격 브랜치 삭제가 막혀 있어 강제 push도 막힐 가능성이 크다 (시도하지 않음). **사용자 컴퓨터에서 실행하는 것을 기준으로 한다** |
| 권장 순서 | ① main 병합·배포·실기기 확인 → ② 필요 없는 브랜치 정리(main만 남기거나 release-prep 포함 2개) → ③ Android 워크플로 Disable → ④ 4-2~4-6 → ⑤ verify-live 통과 확인 → ⑥ Android 워크플로 Enable → ⑦ 모든 복제본 새로 받기 → ⑧ GitHub 지원에 옛 커밋 캐시 삭제 요청 |

## 7. Google Fonts 요청 없애기 — 적용 완료 (2026-11-19, `claude/release-prep`)

아래 방안대로 적용했다. 확인: 화면 보정 화면 한국어 라이트·영어 다크 바꾸기 전후 픽셀 동일, 외부 요청 0개, 임시 배포 사이트에서 `verify_live.py` 통과(글꼴 로드·오프라인). 처음에는 미리 저장 없이 적용했으나, 최종 점검(`tests/fontofflinetest.py`)에서 처음 설치 뒤 오프라인이면 글꼴이 하나도 없고 업데이트 사용자도 13조각이 빠지는 것을 확인해, 설치 때 앱 글자용 101개(1.32MB)를 미리 저장하도록 고쳤다 (`fonts/precache.json`).

| 항목 | 검토 결과 (2026-11-19) |
|---|---|
| 라이선스 | IBM Plex Sans KR, Barlow Condensed 모두 **SIL Open Font License 1.1** (npm `@fontsource/*` 5.3.0 패키지의 LICENSE로 확인). 앱에 넣어 함께 배포 가능, 라이선스 파일을 같이 둔다. 글꼴만 따로 팔 수 없음 |
| 용량 | 쓰는 굵기(Plex 400·500·600, Barlow 500·600)의 글자 조각 288개 = 약 3.6MB를 저장소·Pages에 추가. 앱 글자(982자, 한글 824자)를 그리는 데 필요한 조각은 101개 약 1.3MB이며, 브라우저는 필요한 조각만 받는다 (지금 Google Fonts와 같은 방식) |
| 디자인 | 임시 사본으로 대시보드를 찍어 비교: 한국어·영어 모두 **다른 픽셀 0개**. 외부 요청 25개 → 0개 |
| 오프라인 | 지금과 같다: 처음 쓸 때 받아 서비스 워커가 저장. 원하면 앱 글자에 필요한 101개(약 1.3MB)를 설치 때 미리 저장해 첫 실행부터 오프라인 글꼴 보장 가능 (설치 용량 증가) |
| 개인정보 | 외부 요청이 GitHub Pages 하나로 줄어든다. 개인정보처리방침 3번·Play 데이터 보안 근거에서 Google Fonts 항목 삭제 |

적용한 방안

1. `fonts/`에 woff2 288개와 `OFL-IBMPlexSansKR.txt`, `OFL-BarlowCondensed.txt` 추가, `fonts/fonts.css`에 `@font-face`(unicode-range 그대로)
2. `src/template.html`에서 Google Fonts `preconnect`·`link` 2줄을 `fonts/fonts.css` 링크로 바꾸고 빌드
3. `sw.js`: 캐시 이름을 올리고(`sr-v3`), Google Fonts 처리 줄 정리
4. `.github/workflows/pages.yml` 배포 목록에 `fonts/` 추가, `tools/verify_live.py`에 글꼴 응답 확인 추가
5. `privacy.html`·Play Console 초안의 Google Fonts 문장 정리
6. 관련 테스트: compattest, touchtest, swtest, pwatest + 외부 요청 0개 확인

### 8-2. 실기기 테스트용 APK와 Play 제출용 AAB의 차이

같은 빌드 한 번에 둘 다 만들어진다 (`speedread-android-N` 안에 `app-release.apk`, `app-release.aab`).

| | APK (`app-release.apk`) | AAB (`app-release.aab`) |
|---|---|---|
| 쓰는 곳 | 테스트 기기에 직접 설치 (파일을 옮겨 설치) | Play Console에 올림 (비공개 테스트·프로덕션) |
| 기기에 깔리는 서명 | **업로드 키** 그대로 | Play가 **앱 서명 키**로 다시 서명해 배포 |
| 주소창 | assetlinks.json에 업로드 키 지문이 있어 **지금도 주소창 없음**이 정상 | 앱 서명 키 지문을 assetlinks.json에 넣기 전에는 **주소창이 보임** |
| 함께 설치 | 같은 패키지라 서명이 다른 두 앱은 함께 설치할 수 없다. 한쪽을 지운 뒤 설치 (지우면 기기 안 기록도 지워지므로 먼저 백업 내보내기) | |
| 새 빌드 필요 | 실기기 테스트는 **기존 #5 APK로 가능** (화면은 웹에서 받으므로) | Play 제출에는 새 빌드 권장: 설치 정보 설명 문구(B판)가 들어간 #6. #5도 형식상 올릴 수 있으나 설명 문구가 옛 것 |
| Play Protect | 직접 설치 때 경고가 뜰 수 있음 | 해당 없음 |
