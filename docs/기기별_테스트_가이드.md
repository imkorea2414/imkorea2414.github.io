# 기기별 테스트 가이드 (MacBook · iPad · Android)

같은 웹앱(`https://imkorea2414.github.io/`)을 세 가지 방식으로 연다.

| 기기 | 여는 방법 | 엔진 | 기록 저장 위치 |
|---|---|---|---|
| Android 휴대폰 | 직접 설치한 APK (TWA) | Chrome | 휴대폰 Chrome |
| MacBook | Safari / Chrome 탭, 또는 Dock·앱으로 설치 | WebKit / Chromium | 그 브라우저(또는 설치한 앱) |
| iPad | Safari 탭, 또는 홈 화면에 추가 | WebKit | Safari 또는 홈 화면 앱 (서로 따로) |

**지원 범위 (2026-10-29 결정):** iPadOS·iOS·macOS **Safari 16.4 이상**, Android **Chrome 최신**, Mac **Chrome 최신**. 이보다 낮은 버전은 테스트·지원 대상이 아니다.

**기록은 기기·브라우저·설치 방식마다 따로 저장되고 서로 옮겨지지 않는다.** (v1은 회원가입·서버 저장 없음) 같은 Day를 기기마다 처음부터 시작하는 것이 정상이다.

## 1. 시뮬레이션 테스트와 실제 기기 테스트

| 구분 | 무엇으로 | 확인할 수 있는 것 | 확인할 수 없는 것 |
|---|---|---|---|
| 브라우저 시뮬레이션 (자동) | Playwright Chromium·WebKit, 화면 크기 흉내 | 화면 넘침, 버튼 동작, 훈련 흐름, 기록 저장 로직, 색 대비, 스크립트 오류 | 실제 화면 크기·밝기, 손가락 터치 감각, 화면 꺼짐, 전체 화면, 홈 화면 앱, 오프라인(WebKit), 7일 기록 삭제, 성능 |
| 실제 기기 (사람) | MacBook, iPad, Android 휴대폰 | 위 표의 오른쪽 전부 | — |

WebKit은 Safari와 같은 엔진 계열이지만 **Safari 그 자체는 아니다.** WebKit 시뮬레이션에서 통과해도 실제 Safari에서 확인하기 전에는 "정상"이라고 하지 않는다.

자동 테스트 실행 (저장소 루트에서 `python3 -m http.server 8765`를 켠 상태):

```bash
cd tests
for t in *.py; do python3 $t | tail -1; done                   # Chromium
for t in *.py; do BROWSER=webkit python3 $t | tail -1; done    # WebKit (Safari 계열)
BROWSER=webkit python3 compattest.py                            # 기기 크기별 훑기
```

WebKit을 처음 쓰는 환경에서는 `python3 -m playwright install webkit && python3 -m playwright install-deps webkit`가 필요하다.

## 2. 여는 방법

### MacBook

- **Safari 탭:** 주소 `https://imkorea2414.github.io/` 를 연다.
- **Safari 앱으로 설치 (macOS Sonoma 14 이상):** 메뉴 **파일 → Dock에 추가**. Dock 아이콘으로 열면 주소창 없는 앱 창이 된다. 기록은 Safari 탭과 따로 저장된다.
- **Chrome:** 주소창 오른쪽 **설치 아이콘(모니터+화살표)** 또는 메뉴 **⋮ → 전송, 저장, 공유 → 페이지를 앱으로 설치**.
- 훈련 중 키보드: `Space` 일시정지/계속, `←` `→` 빠르기 또는 책장 넘기기, `↑` `↓` 빠르기, `PageUp/PageDown`, `Enter`(책장 넘기기).

### iPad

- **Safari 탭:** 주소를 연다.
- **홈 화면에 추가:** Safari 주소창 옆 **공유(□↑) → 홈 화면에 추가 → 추가**. 홈 화면 아이콘으로 열면 주소창 없이 열린다.
- **권장: 홈 화면 앱으로 테스트.** Safari 탭에서는 사이트를 7일 동안 열지 않으면 Safari가 기록을 지울 수 있다(Apple의 추적 방지 정책). 홈 화면 앱은 이 삭제 대상이 아니다.
- 지원 버전: **iPadOS 16.4 이상** (화면 켜짐 유지·전체 화면 기능 지원). 홈 화면 앱에서 화면 켜짐 유지는 **iPadOS 18.4 이상**에서 동작한다. 그보다 낮으면 테스트 동안 **설정 → 디스플레이 및 밝기 → 자동 잠금 → 안 함**으로 둔다.
- 키보드(Magic Keyboard 등)가 있으면 Mac과 같은 키가 동작해야 한다.

### Android

- 기존 빌드 #4 APK를 그대로 쓴다 (`docs/실기기_테스트_체크리스트.md`).

## 4. 기기별 추가 항목

### MacBook (Safari, Chrome 각각)

- ☐ 창 크기를 줄이고 늘려도 훈련 원 배치가 창 안에 맞춰진다
- ☐ 훈련 시작 시 전체 화면이 된다
- ☐ 훈련 중 `Esc` → 전체 화면이 풀린다. 훈련이 **일시정지**된다 (4번 수정)
- ☐ `Space`로 일시정지·계속, 화살표로 빠르기, `→`/`Enter`로 책장 넘기기 (제2단계 C)
- ☐ 트랙패드로 원을 짚는 도입 단계가 된다
- ☐ 트랙패드 두 손가락 스와이프(뒤로 가기) → 훈련 중이면 나가지 않고 일시정지
- ☐ Safari "Dock에 추가" 앱에서 기록이 Safari 탭과 따로인 것 확인 (정상)

### iPad (Safari 탭, 홈 화면 앱 각각)

- ☐ 세로·가로로 돌려도 원 배치가 다시 맞춰진다
- ☐ Split View(반 화면)·Slide Over(좁은 창)에서도 화면이 잘리지 않는다 (아래 1번 문제 참고)
- ☐ 손가락 터치로 원 짚기, 오른쪽 아래 탭으로 책장 넘기기
- ☐ 빠르기 −/+ 를 빠르게 두 번 눌러도 화면이 확대되지 않는다 (아래 5번 문제)
- ☐ 훈련 중 길게 눌러도 글자 선택·확대경이 나타나지 않는다
- ☐ 화면 왼쪽 끝에서 밀기(뒤로 가기) → 훈련 중이면 일시정지
- ☐ Safari 탭: 훈련 시작 시 전체 화면이 된다 (홈 화면 앱은 원래 주소창 없음)
- ☐ 홈 화면에 추가할 때 이름이 "속독 트레이닝"으로 나온다 (아래 7번)
- ☐ 저전력 모드에서 훈련 시간이 실제 시간과 맞는다 (스톱워치로 3분 비교)

### 문제없음으로 판단한 것 (코드 분석, 실기기 확인은 남음)

- 터치·마우스·트랙패드: Pointer Events로 하나로 처리 (Safari 13 이상)
- 훈련 타이머: 실제 흐른 시간(프레임 간격, 최대 0.1초)으로 계산, 화면이 가려지면 일시정지
- 화면 회전·창 크기 변경: 훈련·독서·진행 화면 모두 다시 배치
- 기록 저장: localStorage, 실패해도 앱이 멈추지 않게 처리
- 뒤로 가기: Android 버튼, iPad 가장자리 밀기, Mac 두 손가락 스와이프 모두 같은 방식(history)으로 처리
- 오프라인: 서비스 워커 (Safari 지원). WebKit 시뮬레이션에서는 확인 못 함 → 실기기 확인
