# 실기기 최종 테스트 (중요도 순서, 합격 기준, 오류 기록)

2026-11-20 개정. 기준: `claude/release-prep` `06a84fa` (자동 테스트 19개, Chromium·WebKit 통과. **WebKit 오프라인 단계는 자동 테스트로 확인하지 못함 → 미완료**, 아래 ★ 항목은 실기기에서만 확인된다).

## 0. 먼저 알아 둘 것

- **Android 앱(APK·Play)은 웹 주소 `https://imkorea2414.github.io/`의 내용을 그대로 보여 준다.** 앱 안의 화면은 GitHub Pages에 배포된 버전이다. 지금 공개 사이트는 옛 버전(main: 책 제목 표시, Google Fonts, 옛 오프라인 캐시)이므로, **최종 실기기 테스트는 main 병합·배포 뒤에 한다.** 그 전에 하면 옛 버전을 시험하게 된다.
- 버전 확인: 대시보드 맨 아래 문구가 **"이 앱은 한 속독 훈련서(이 앱에서는 '원전')의 훈련 과정을…"** 이면 최신(B판). "『과학적 속독법』"이 보이면 옛 버전 → 테스트를 미룬다.
- **설치 파일:** GitHub → Actions → "Android app bundle" → 실행 **#6**(11/20, 통합 브랜치, versionCode 6) → Artifacts `speedread-android-6` → 압축 풀기 → `app-release.apk` 설치 (보관 기한 2027-02-18). **이 APK도 화면은 공개 웹 주소에서 받아 오므로, main 배포 전에는 옛 버전이 보인다.** APK로 확인되는 것은 설치·실행·서명(주소창 없음)뿐이다. Play 비공개 테스트가 시작되면 Play에서 설치한 앱으로도 한 번 더 한다 (두 앱은 서명이 달라 함께 설치할 수 없음: 한쪽을 지운 뒤 설치).
- **배포 전에 최신 버전을 확인하려면 0-1의 로컬 방법을 쓴다** (공개 주소를 만들지 않음).
- 제2·3단계 원 크기·간격은 아직 **추정값**이다. 실기기 테스트에서 "책과 크기가 다르다"는 결과가 나와도 값을 고치지 않고 기록만 한다 (실측값을 받은 뒤 반영).

## 0-1. 공개 배포 없이 최신 버전 확인하기 (2026-11-20 검토)

`python3 tools/serve_local.py`는 Pages에 올라가는 것과 같은 서비스 파일만 모아 **전도사님 컴퓨터 안에서만** 띄운다 (개발 문서·원본은 404, 공개 주소 없음). localhost 주소는 공개 사이트·설치한 앱과 주소가 달라 **기록이 따로 저장되므로 기존 기록에 영향이 없다.**

| 방법 | 확인할 수 있는 것 | 확인할 수 없는 것 | 전도사님이 할 일 |
|---|---|---|---|
| **A. Android 휴대폰 + USB 포트 포워딩 (권장)** | 휴대폰 Chrome에서 `http://localhost:8765` = 최신 버전. localhost는 보안 출처라 **오프라인 저장·글꼴·화면 켜짐 유지·전체 화면·터치·백업까지 공개 사이트와 같은 조건**. "홈 화면에 추가"로 설치한 화면도 확인 가능. 오프라인 = 컴퓨터에서 서버를 Ctrl+C로 멈춤 | TWA 앱 자체(앱 아이콘 실행, 주소창 없음 P1-1) | ① 컴퓨터에 Chrome·Python 3, 저장소 내려받기(GitHub → 브랜치 `claude/release-prep` → Code → Download ZIP) ② 휴대폰 설정 → 휴대전화 정보 → 빌드 번호 7번 눌러 개발자 옵션 → USB 디버깅 켜기 ③ USB 연결, 휴대폰에서 허용 ④ 압축 푼 폴더에서 `python3 tools/serve_local.py` ⑤ 컴퓨터 Chrome `chrome://inspect` → Port forwarding → `8765` / `localhost:8765` 추가·체크 ⑥ 휴대폰 Chrome에서 `localhost:8765` (준비 약 15분) |
| **B. Mac 안에서 (Safari·Chrome)** | `http://localhost:8765`도 보안 출처 → Mac 항목 전부 + **실제 Safari 엔진으로 오프라인·글꼴 확인** (자동 테스트의 WebKit 오프라인 SKIP 중 데스크톱 Safari 부분을 채움) | iPad·iPhone의 Safari, 홈 화면 앱 | Mac에서 ①·④ 후 Safari로 접속, 오프라인은 서버 멈춤 |
| C. 같은 Wi-Fi (`--lan`) | iPad·휴대폰을 USB 없이: 화면 배치, 터치, 훈련 진행, 1분 측정, 백업, 두 번 탭 확대 (11/20 확인: 오류 없이 열림) | **보안 출처가 아니라 서비스 워커·오프라인·화면 켜짐 유지 API가 아예 없음** (11/20 확인), 설치 | `python3 tools/serve_local.py --lan` 후 표시된 `http://IP:8765`를 iPad에서 열기. 컴퓨터 방화벽이 물으면 "허용" |
| D. iPad에서 오프라인까지 | 로컬 HTTPS 인증서를 만들어 iPad에 신뢰 설정하면 가능 | — | 인증서 생성·설치·삭제 관리가 번거롭고 잘못 남기면 보안 위험 → **권장하지 않음** (iPad 오프라인은 배포 뒤 확인) |
| E. 기존 claude.ai 프로토타입 링크 갱신 | 링크를 가진 사람만 열 수 있음 | 서비스 워커는 github.io·localhost에서만 켜지도록 되어 있어 오프라인 불가, 전체 화면·화면 켜짐이 막힐 수 있음. 이미 테스터에게 공유된 링크라 내용을 바꾸면 테스터에게도 바로 보임 | 하려면 별도 결정 (Claude는 하지 않았음) |
| F. 새 APK만 설치 | 설치·실행·서명 | **최신 웹 기능은 확인되지 않음** (앱이 공개 주소의 옛 버전을 보여 줌) | — |

정리: **A(Android) + B(Mac Safari)로 배포 전 확인 → 배포 뒤 TWA 앱(P1-1)과 iPad 오프라인(★)만 다시 확인.** 0장의 "B판 문구" 확인은 A·B·C에서도 같다.
